# 말하는 도감 (코드명 voicedex) — 마스터 프롬프트

이 문서는 프로젝트의 확정 사양과 작업 순서를 정리한 기준 문서다. 모든 작업은 이 문서를 따른다.

## 1. 개요

- 대상: 미취학 아동(3~6세).
- 핵심 놀이: 아이가 그림을 보고 이름을 소리 내어 말해 맞춘다.
- 플랫폼: **Flutter + Flame 엔진 기반 iOS/Android 앱으로 확정.**
- 번들 ID·패키지 이름(가제): `com.example.voicedex`, 앱 표시 이름(가제): "말하는 도감". 출시 전 교체한다(교체 지점은 `README.md`).

## 2. 절대 제약

1. 아이 화면에 글자 없음. (부모 화면·개발자 화면만 예외)
2. 점수·별·실패 판정 없음.
3. 광고 SDK 없음, 제3자 분석 도구 없음.
4. 개인정보 수집 없음, 계정 없음. 저장은 기기 로컬에만 한다.
5. 일러스트는 전부 오리지널. 기존 IP·캐릭터·영화 디자인 참조 금지, 외부 이미지 사용 금지.
6. 그림자 에셋은 색칠 그림과 **같은 벡터 소스**에서 단색으로 파생한다. (별도로 그리지 않는다)

## 3. 월드와 단계 구성

- 월드 3개, 순서 고정: **동물 → 탈것 → 공룡**.
- 월드마다 3단계:
  1. 1단계: 색칠된 그림을 보고 이름 말하기
  2. 2단계: 그림자와 그림을 드래그해 짝맞추기
  3. 3단계: 그림자만 보고 이름 말하기
- 월드당 12종.
- 스테이지당 6문항, 해당 월드 12종에서 랜덤 출제.
  - 한 스테이지 안에서는 같은 종이 중복 출제되지 않는다.
  - 도감에 아직 없는(미보유) 종에 가중치를 둬서 더 자주 나오게 한다.
- 마지막 혼합 스테이지: 세 월드를 섞어 **그림자만 보고 말하기 7문항**.

## 5. 음성 인식·정답 판정

- **부분 일치 인정.** 아이가 이름의 일부만 말해도 맞게 처리한다.
- 공룡 단축형 인정:
  - 티라노(티라노사우루스), 트리케라(트리케라톱스), 스테고(스테고사우루스), 브라키오(브라키오사우루스), 프테라노(프테라노돈), 안킬로(안킬로사우루스), 파라/파라사우(파라사우롤로푸스), 스피노(스피노사우루스), 랩터(벨로시랩터), 모사(모사사우루스), 디플로(디플로도쿠스), 플레시오(플레시오사우루스)
- 동의어: **굴착기 = 포크레인**.
- 유사 발음 허용: 곰, 배처럼 짧은 단어는 인식기가 비슷한 발음으로 받아 적는 경우를 허용 목록으로 처리한다.
- **인식 실패와 오답을 구분한다.** 아무것도 인식되지 않았거나 신뢰도가 낮은 경우(인식 실패)는 다시 말해 보도록 유도하고, 다른 이름이 인식된 경우(오답)는 별도로 처리한다. 둘 다 실패 판정·감점은 없다.
- **정답 목록(정식 이름·단축형·동의어·유사 발음)은 코드가 아니라 데이터 파일로 분리한다.**
- **힌트 (확정, 단계식):** 오답(다른 이름이 인식됨)마다 한 단계씩 올라간다. 인식 실패는 오답으로 세지 않고 힌트 없이 다시 말해 보도록 한다(단계도 그대로).
  1. 1번째 오답 → **특징 힌트** 한 문장(그림자에서도 보이는 형태 특징 위주, 예: 코끼리 "코가 아주아주 길어!"). 종별 문장은 `assets/data/animals.json`의 `feature_hint`.
  2. 2번째 오답 → **앞글자**(예: "코..."). 한 음절 이름은 받침을 뺀 소리(곰 → "고...")로 정답을 그대로 말하지 않는다. `animals.json`의 `hint`.
  3. 3번째 오답부터 → **정답을 들려주고 따라 하게** ("코끼리! 따라 해 볼까?") → 아이가 따라 말하면 정답 처리("그래, 코끼리! 잘 따라 했어!"). 계속 다르게 말하면 이 단계를 반복한다(실패 판정 없음).
  - 문항이 바뀌면 처음 단계로 돌아간다. 힌트를 한 번이라도 받은 문항은 §6의 3층 표시만 붙지 않는다.
- **안내 음성 (확정):** 지금은 기기 TTS(ko-KR)를 우선 쓰고, 나중에 녹음 파일로 교체한다. 이를 위해 음성 출력은 인터페이스로 분리하고, 대사는 키→문장 데이터(`assets/data/voice_lines_ko.json`)로 둔다.

## 6. 보상 (3층 구조, 점수·별 없음)

1. 정답 즉시: 소리 + 움직임(그림이 반응).
2. 스테이지 끝: 도감이 열리고 만난 종이 채워진다. 이번에 맞힌 종이 차례로 도감 칸으로 날아가 "찍히고", 새로 열린 종은 더 크게 강조한다.
3. 단계별 도감 표시: 1단계 완료 → 칸(색칠 그림), 2단계 → 테두리, 3단계 → 금테.
   - **힌트를 쓴 문항:** 도감 칸은 똑같이 열리고, 그 단계의 3층 표시만 붙지 않는다. "아직 안 받은 상태"로 남을 뿐 실패 표시는 하지 않는다(데이터에도 실패 기록 없음). 나중에 힌트 없이 맞히면 그때 받는다. 한 번 받은 표시는 내려가지 않는다.
- **출제 가중치 (확정):** 도감 미보유 종은 가중치 3(보유 1)으로 더 자주 나오고, 스테이지마다 미보유 종을 최소 2종(남은 게 그보다 적으면 남은 전부) 반드시 넣는다. 순서는 섞는다. → 스테이지를 끝낼 때마다 미보유가 최소 2종씩 줄어 12종 도감은 빈 상태에서 최대 4스테이지 안에 반드시 다 찬다(`lib/quiz/question_picker.dart` `QuestionPicker.dexAware`, 테스트로 검증).
- **진행 저장:** 기기 로컬만(shared_preferences: iOS NSUserDefaults / Android SharedPreferences / 웹 localStorage). 계정·네트워크 없음. 도감은 스테이지를 끝냈을 때 반영된다(중간에 나가면 그 스테이지는 반영 안 됨).

### 메인 화면·도감 (확정, 아이 화면이라 글자 없음)
- 시작(재생 버튼) → 메인 화면: 월드 입구(큰 그림 버튼, 누르면 1단계 시작)와 도감 버튼(책 아이콘). 들어올 때 짧은 환영 음성, 버튼을 누르면 무엇인지 음성으로 알려준다("동물 나라!", "내 도감!").
- 잠긴/유료 월드는 아이 화면에 보이지 않는다(`WorldCatalog.visibleToChild`).
- 도감: 월드의 12칸. 못 만난 종은 그림자, 만난 종은 색칠 그림 + 단계 표시. 칸을 누르면 이름을 들려준다("곰이야!"). 못 만난 종은 "누구일까? 곧 만나러 가자!"(이름 공개 안 함). 만난 종은 그림이 살짝 움직인다. 집 버튼으로 돌아간다.

> 메모(정답 공개 연출 아이디어, 미확정): 그림자 카드를 보여 주고, 맞히면 같은 자리에서 컬러 그림이 드러나며 이름을 음성으로 들려준다. 글자는 띄우지 않는다.

## 8. 그림체와 에셋

세부 규칙(비율·색·얼굴·필렛·자세·혼동 쌍·체크리스트)은 **`docs/STYLE_GUIDE.md`를 따른다.** 이 절은 확정된 큰 방향만 적는다.

- **그림체 (확정):** 귀여운 유아용 일러스트. 2~2.5등신 아기 동물, 둥근 외곽, 파스텔 평면 채색 + 옅은 음영 1단계, 점 눈, 외곽선 없음.
- **그림자 (확정):** 컬러 그림과 같은 벡터 소스의 외곽을 단색 `#1E1E1E`로 채운 것. 회색 톤·그라데이션 없음. 종의 식별 특징은 몸통과 겹치지 않고 **바깥 윤곽에 걸려야** 한다.
- **시점 (확정):** 종마다 가장 알아보기 쉬운 자세를 쓴다(STYLE_GUIDE §7 자세 배정표). 모두 왼쪽을 보고, 펭귄만 정면이다.
- **에셋 파이프라인:**
  - 코드: `tools/cute/` — `species/<id>.py`(종별 정의), `common.py`(공용), `build.py`(SVG 생성), `sheet.py`(검사 시트).
  - 산출물: `assets/draft_silhouettes/cute/<id>_color.svg`, `<id>_shadow.svg`.
  - 현재 **초안(DRAFT) 단계**다. 실루엣 검사 경과와 남은 약점은 `docs/silhouette_check/REPORT.md`.

## 10. 작업 순서 (단계마다 확인을 받고 다음 단계로 넘어간다)

> 웹 테스트 빌드(https://ul-dong.github.io/voicedex/)는 앱 전에 흐름을 확인하기 위한 **내부 테스트용이며 출시 대상이 아니다.** 크롬의 Web Speech API는 음성을 Google 서버로 보내 인식하므로 앱의 기기 내 인식 원칙이 적용되지 않는다. 앱 버전은 기기 내 인식 원칙을 그대로 지킨다(README "웹 버전").

1. 동물 12종 실루엣을 한 화면에 놓고 서로 구분되는지 검사 — **완료 (2026-11-12)**
2. 1종을 완성해 그림체 고정 — **완료 (2026-11-12)**, 동물 12종 초안까지 진행
3. 1단계 퀴즈 + 음성 인식 검증 — **다음 작업**
4. 나머지 단계(2·3단계, 혼합 스테이지)와 도감
5. 과금과 페어런탈 게이트
